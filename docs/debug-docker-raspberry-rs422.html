Reflow Oven · Backend · .NET 10 · Dev Container

Debug na Raspberry via Docker — .NET só no container

Depurar o backend rodando dentro de um container na Pi, com o SDK .NET e o debugger no Docker. A Raspberry só precisa do Docker — nada de .NET instalado no host — e a serial RS422 é repassada ao container.

Como funciona

Usamos Dev Containers sobre Remote-SSH: o VS Code reabre o projeto dentro de um container na Pi cuja imagem (mcr.microsoft.com/dotnet/sdk:10.0) já traz o SDK. Build, processo da API e o debugger (vsdbg) rodam no container; o F5 funciona como local. A config é imagem-based (sem docker-compose) com mount explícito — ver Armadilhas para o porquê.

Diferença para o outro guia

Em debug-remoto-raspberry-rs422.html o .NET fica instalado no host da Pi (Remote-SSH puro). Aqui o .NET vive só no container — escolha este se não quer SDK no sistema da Raspberry.

1 · As 3 camadas

São três camadas encaixadas — o código e o .NET ficam na mais interna:

┌──────── NOTEBOOK ────────┐ SSH ┌────────── RASPBERRY PI (só Docker) ──────────┐ │ VS Code (UI) │ ◀────▶ │ ┌──── CONTAINER (imagem dotnet/sdk:10.0) ──┐ │ │ • RUN AND DEBUG, PORTS │ │ │ build · vsdbg · ReflowOven.Api │ │ │ │ │ │ /workspace = a pasta REAL da Pi │ │ │ │ │ │ │ device: /dev/ttyS0 (RS422) │ │ │ │ │ └────────┼─────────────────────────────────┘ │ │ │ │ --network=host │ │ │ │ ┌───────▼──── Postgres (no host) ──────────┐ │ │ │ │ │ docker compose up -d → localhost:5432 │ │ │ │ │ └───────────────────────────────────────────┘ │ └──────────────────────────┘ └───────────────────────────────────────────────┘
  • O SDK, o build e o vsdbg estão na imagem do container — o host da Pi não tem .NET.
  • /workspace é a pasta real do repo na Pi (mount explícito; ver Armadilhas D).
  • A serial é repassada ao container por --device; o System.IO.Ports.SerialPort abre o /dev/tty* real.
  • O Postgres roda no host da Pi; com --network=host a API o alcança em localhost:5432 (igual ao appsettings).

3 · Pré-requisitos

No notebook

  • VS Code com Remote - SSH (ms-vscode-remote.remote-ssh) e Dev Containers (ms-vscode-remote.remote-containers).
  • SSH configurado para a Pi (no notebook). Crie/edite o ~/.ssh/config e ajuste as permissões:
mkdir -p ~/.ssh

cat > ~/.ssh/config <<'EOF'
Host reflow-oven
    HostName raspberrypi.local
    User reflow-oven
    IdentityFile ~/.ssh/MASTER_id_ed25519
    IdentitiesOnly yes
EOF

chmod 700 ~/.ssh
chmod 600 ~/.ssh/config
chmod 600 ~/.ssh/MASTER_id_ed25519        # chave privada
chmod 644 ~/.ssh/MASTER_id_ed25519.pub    # chave pública

ssh reflow-oven        # testa a conexão
Os campos / as permissões

HostName raspberrypi.local resolve por mDNS (mesma LAN; se não resolver, use o IP). User reflow-oven é o usuário na Pi e IdentitiesOnly yes força usar só essa chave. Os chmod são obrigatórios: o SSH ignora a chave/config com permissão frouxa. Ajuste o nome da chave se a sua for diferente.

Na Raspberry

  • Docker + Docker Compose (você já tem). Não precisa de .NET no host.
  • Raspberry Pi OS 64-bit (arm64) — necessário para o vsdbg e a imagem arm64 do SDK.
  • git instalado (sudo apt install -y git) e o repositório clonado na Pi (próximo passo).

1 Clonar o repo na Pi

O container lê o clone da Pi — o código precisa estar lá. No terminal da Pi (SSH):

cd ~
git clone https://github.com/LegiusAndrade/reflow-oven-backend.git
cd reflow-oven-backend
git config --global user.name  "Seu Nome"       # se ainda não configurou
git config --global user.email "seu@email"
ls .devcontainer/        # deve listar devcontainer.json
Editou no note?

O container não usa os arquivos do note — usa o clone da Pi. Toda alteração feita no note só chega à Pi via git push (no note) + git pull (na Pi). Veja Atualizar a config.

2 Conectar Remote-SSH na Pi

Ctrl+Shift+P → Remote-SSH: Connect to Host → reflow-oven (ou clique em “reflow-oven-backend [SSH: reflow-oven]” no Recent).

Confirme que está na Pi antes de seguir:

  • canto inferior esquerdo mostra “SSH: reflow-oven”;
  • no terminal, o prompt é reflow-oven@raspberrypi:~$ (usuário reflow-oven, não lsilva).

3 Abrir a pasta e Reopen in Container

  1. File → Open Folder → /home/reflow-oven/reflow-oven-backend.
  2. Ctrl+Shift+P → “Dev Containers: Reopen in Container”.

Na primeira vez o Docker da Pi puxa a imagem dotnet/sdk:10.0 (arm64) e o C# Dev Kit baixa o vsdbg no container. Ao terminar, a barra inferior mostra “Dev Container: Reflow Oven … @ reflow-oven”.

A ordem importa

“Reopen in Container” cria o container na máquina pra onde a janela atual aponta. Faça-o só depois de estar na janela Remote-SSH da Pi (passo 2). Se fizer numa janela local, sobe no note (ou pior, num híbrido quebrado — ver Armadilhas B/C).

4 Conferir que deu certo

No terminal integrado (agora root@<hash>:/workspace#):

pwd            # /workspace
ls             # src  docs  tests  ReflowOven.slnx …  (o REPO, não Desktop/Documents)
dotnet --info  # mostra o SDK 10 (arm64) da imagem

Se o ls mostra o repositório (e não a sua home), o mount está certo e o ambiente está pronto. O C# Dev Kit inicializa o language server localizando o .NET em /usr/share/dotnet/dotnet:

5 Postgres + build + F5

Postgres (no host da Pi)

A API migra/seed no startup, então o banco precisa estar no ar. No host da Pi (terminal SSH, fora do container):

cd ~/reflow-oven-backend
docker compose up -d        # Postgres em localhost:5432
docker compose ps           # "healthy"

Com o --network=host do dev container, a API o alcança em localhost:5432 — a connection string padrão do appsettings já bate, sem mudar nada.

Build / Debug

No container: F5 na config “Debug API (Docker na Pi)” (compila com a task build (container) e sobe com o debugger). Ou no terminal: dotnet run --project src/ReflowOven.Api.

Esperado e benigno

O debugger parando em ValidationAppException/NotFoundException/ConflictException é fluxo de validação (viram 400/404/409). Para não ser interrompido: RUN AND DEBUG → BREAKPOINTS, desmarque “User-Unhandled Exceptions”.

6 Ligar a serial RS422

  1. Descubra o device na Pi: ls -l /dev/ttyAMA0 /dev/ttyS0 /dev/ttyUSB* (e dmesg | grep -i tty).
  2. No .devcontainer/devcontainer.json, acrescente o --device ao runArgs: 
    "runArgs": ["--network=host", "--device=/dev/ttyAMA0"]
  3. Dev Containers: Rebuild Container para recriar com a serial.
Sem grupo dialout

O container roda como root, então acessa /dev/tty* direto.

O driver RS422 é um stub

Rs422PowerBoard lança NotSupportedException em tudo. Com Hardware__Mode=Rs422 a API sobe, mas chamadas à placa estouram — é o que você vai implementar em src/ReflowOven.Infrastructure/Hardware/Rs422PowerBoard.cs (embrulhar o SerialPort + protocolo do STM32). Enquanto isso, use Hardware__Mode=Simulated.

⚠️ Armadilhas que pegam (leia!)

Custaram horas; cada uma tem um sintoma específico.

#ArmadilhaSintoma / correção
A SSH ≠ Container SSH: reflow-oven te leva ao host cru da Pi (sem .NET → dotnet: not found). É preciso o 2º passo, Reopen in Container, pra entrar no Docker (com .NET).
B “Reopen” cria onde a janela aponta Se a janela tem a pasta do note aberta (/home/lsilva/…), o container sobe no note. Tem que estar na janela Remote-SSH da Pi (paths /home/reflow-oven/…) antes de dar Reopen.
C Docker context apontando pra Pi Se houver um docker context ativo tipo ssh://reflow-oven e você der Reopen numa janela local, o container sobe no Docker da Pi mas com os caminhos do note → /workspace vazio. Volte ao contexto local: docker context use default e use Remote-SSH.
D Mount relativo no compose Com docker-compose de 2 arquivos, ..:/workspace resolve a partir da raiz do projeto e acaba montando a pasta-pai/home (o ls mostra Desktop/Documents). Por isso usamos config imagem-based com workspaceMount: ${localWorkspaceFolder} (explícito).
E Download do SDK (polkit) No polkit authentication agent found: o C# Dev Kit tentava instalar um SDK global. Resolvido por dotnet.sdk.enableAutoAcquisition: false + dotnetAcquisitionExtension.sharedExistingDotnetPath (já no devcontainer.json).
F Settings no lugar errado Esses settings vão no devcontainer.json — não no User settings do note. No note eles apontam pra /usr/share/dotnet (que não existe lá) e quebram o C# local.
G Alteração não reflete na Pi O container usa o clone da Pi. Editou no note? git push (note) → git pull (Pi) → Rebuild Container. Ver abaixo.

Atualizar a config depois

Quando mudar algo do .devcontainer/ ou do código no note:

# no NOTE
git add .devcontainer/ .vscode/
git commit -m "…"
git push

# na PI (terminal SSH)
cd ~/reflow-oven-backend && git pull
# se reclamar de alteração local no .devcontainer:
#   git checkout -- .devcontainer && git pull

Depois, no VS Code (janela da Pi): Dev Containers: Rebuild Container para aplicar a config nova.
